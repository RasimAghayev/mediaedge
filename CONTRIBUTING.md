# Contributing to MediaEdge

Thank you for considering contributing to MediaEdge! This document outlines the
process for contributing code, documentation, and infrastructure changes.

## How to Contribute

1. **Find or create an issue.** Every change starts with a GitHub issue. Follow
   the issue template and include the required fields (Objective, Context,
   Architecture Requirements, Implementation Prompt, Subtasks, Tests, Security,
   Acceptance Criteria, Definition of Done, PR Requirements).
2. **Create a branch.** Branch names must follow
   `feature/ISSUE-<n>-<slug>`, `infrastructure/...`, `bugfix/...`, or
   `hotfix/...`.
3. **Implement.** Write code, tests, and documentation. No AI signatures
   (no `Co-Authored-By`, no "Generated by AI" footers, no agent-internal notes).
   Use plain Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`) with an
   optional `Refs: #<issue>` trailer.
4. **Open a PR.** Target the `test` branch. Link the related issues in the PR
   body (`Fixes #<issue>`).
5. **Review & merge.** CI must be green (lint, format, typecheck, tests,
   security scans). `main` only accepts PRs from `test`.

## Rust Conventions

* Edition 2024.
* `cargo fmt` and `cargo clippy -D warnings` must pass.
* Use `cargo-chef` layered Docker builds and distroless images.
* Add cross-file dependency comments at call sites (see CLAUDE.md).
